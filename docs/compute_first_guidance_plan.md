# MCMer 收尾计划：最小闭环后封档

本文件是唯一执行计划；执行规则见 `AGENTS.md`。重定向日期：2026-11-10。用户最新目标为“最小闭环，然后对此项目封档”，取代此前继续建设通用数学建模 agent 的路线。

## 目标与执行判断

**GO：收缩范围并完成收尾；当前不满足封档验收。**

目标是在现有实现上完成一个非生物真实数据子任务，从输入、模型生成到实际计算、独立核验和报告交付均可重放，然后冻结版本、保存证据并结束开发。不以通用 agent 能力、竞赛整题覆盖率或优于 Codex / Claude Code 为完成条件。

最小交付按**现有后端流程与可复现报告**定义；不要求建设新的前端、生产 harness 或生成代码运行器。任务范围必须在调用模型前冻结，具体案例由 C1 的运行证据确定，不能事后选择成功样本或把数据读取冒称解题。

- **性质**：技术收尾与交付，不再是平台研发。
- **包含**：一个明确子任务、当前生产流程、真实 Flash 调用、计算结果、独立验证、现有报告/导出、复现说明、已知限制、最终 Git 同步。
- **不做**：H2–H5 的自主循环、专用沙箱、对照实验、默认调度替换、跨题族整题验收；SDK 接入、多 agent 平台、新领域算子目录、界面重做、部署扩张。
- **历史未结问题**：保留真实状态，只有阻塞本次冻结任务的缺陷才进入修复；其他问题作为封档限制，不再自动产生下一研发阶段。
- **判断归属**：工程由测试与实际运行裁决；数值由独立重算及适用检查裁决；任务完成度逐条对照事前冻结清单。模型、报告审核 PASS、测试数量均不能单独宣布闭环完成。
- **置信边界**：单个子任务只能证明这个演示范围可用；不能改变 G1 三题 0/3 的历史事实，也不证明泛化或整题解答能力。

## 封档验收标准

以下条件必须同时成立：

1. **任务明确**：记录原题来源、原件 SHA、选定子任务和不包含的要求。若是基于真题附件重新限定的分析任务，明确标为派生子任务，不冒称完成原题某问。
2. **真实生成与执行**：以现有 Guidance 默认工厂运行，真实模型仅用 `deepseek-flash`；形成实际数值或明确条件下的数学结果。不得手写最终 ModelIR、修补模型输出、绕过来源/数学门禁或抄入独立参考答案来冒充闭环。
3. **独立核验**：从原件另行读取并重算核心结果，核对来源、单位、变换和适用数学检查。回归/预测任务必须区分拟合和预测；涉及预测时检查时间切分、泄漏和基线。验证未覆盖的范围明确披露。
4. **用户可取得结果**：现有报告/导出包含任务范围、方法、核心数值、必要图表或表格、证据引用和局限；关键结果不能只存在内部 JSON 中。代码执行成功或阻断说明生成成功都不算这项通过。
5. **可复现**：在全新任务目录用冻结的原始响应离线重放计算与验证，给出运行命令、环境/依赖、输入摘要和结果容差；同时给出可选真实 API 重跑命令。离线重放不宣称重新生成了模型。
6. **可保存**：最小复现材料随 Git 或明确交付包保存并列出校验清单；不能仅依赖可能被清理的 `backend/.local/`。密钥、配置和全量历史响应不进入提交。记录最终提交/版本和远端一致性。
7. **诚实结束**：封档说明列清已完成、未完成与未测试范围。通过以上门槛后停止新增功能，不因发现下一项优化而自动续建。

这里的“封档”先指最终版本、材料与状态冻结，不等于删除本地文件、删除远端仓库或现在立即设置远端只读；平台只读设置留到最后核对，不阻塞当前可逆工作。

## 现状摘要

1. **核心流**：API → `core.workflow` → Guidance / Polish。Guidance 为原件 → InputCatalog/EvidenceProfile → 拆题 → 来源许可 → ModelIR → 数学审核及一次修订 → 编译/执行 → 分层验证 → 指导/导出；目前仍是固定阶段流程。
2. **最危险的边界**：来源解释/独立复核可能共同误判，计算成功也不等于数学结论充分；结果还可能未完整呈现在指导出口。收尾不能以降低验收等级掩盖这些问题。
3. **本次修改**：将通用 agent 路线替换为“单任务闭环 → 独立复现 → 封档”；同步执行规则。业务代码、默认入口、配置、算子和已有证据均未改。
4. **完成项**：C0 目标重定向。H1 已完成能力压缩为下文不变量；本次文档修改不声称重跑历史 902 项测试或通过任何真实题。
5. **下一项**：C1 冻结唯一演示任务及验收标准；当前还没有满足新标准的闭环，因此项目尚未封档。
