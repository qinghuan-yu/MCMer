- 类型与范围：技术/质量改进；Guidance 的事实作用域/覆盖、静态数据绑定、数学声明构造、模型充分性、依赖失效和生成预算。

## 已锁定不变量

1. InputCatalog/EvidenceProfile 是题面与附件唯一证据入口；精确核验文档、列/单元格和索引顺序，拒绝错列、错序、伪来源及静态 artifact 前缀绕过。
2. ProblemSpec 的事实、歧义和依赖有强类型作用域；拒绝未知符号、跨子题引用及依赖环；Draft 单向提升到 canonical。
3. ModelIR 支持类型化组件和运行时参数物化；不执行任意生成代码，不使用题名/题号路由。
4. 按子题保留独立成功结果；失败/跳过沿依赖传播，其参数、结果和图表不得污染成功子题。
5. 工程执行、证据支持、模型充分性分别报告，不把子集成功、Guidance 审核或求解器 success 当整题验收。
6. 注册、领域算法、生成合同、验证和呈现各有 owner；共享写作/图表归 core，Guidance/Polish 直接导入实现，无兼容门面。
7. 行为改动先 RED 后 GREEN；内部调用方直接迁移，保留公共协议和数学运算行为。
8. R1 已锁定：每个子题的 FactScope 是不可变完整快照；FactCoverage 单独记录阶段/节点到事实的多对多引用。已覆盖事实仍可重复引用；只提交成功阶段的覆盖，失败尝试不留痕；未知/跨作用域与最终漏覆盖仍拒绝。canonical 路径继续由系统组装。
9. R2 已锁定：生成侧静态参数只允许 fact/table_column/table_range 类型化绑定，不接收静态数值数组或自拼切片路径。程序读取原始值、对齐索引、生成逐值来源；fact绑定自动登记来源事实。表格显式单位必须匹配原文后缀，只有纯百分号归一为比例，复合单位保留原尺度；不从模型声明创造单位。

## 核心流与迁移边界

```text
原件 → InputCatalog/EvidenceProfile → ProblemSpec 子题事实快照
  → 架构 + 独立覆盖账本 → 类型化绑定与确定性物化 → 变量/目标/约束共同声明
  → 内部 ModelIR → Review → 编译/执行 → 独立验证 → Guidance/ZIP
API → core 路由 → guidance / polish → 共用写作、图表、导出
```

R1 的事实快照只负责可见性，覆盖账本记录事实到节点的多对多引用。R2 复用既有 canonical 参数和证据解析器。R3 按实际失败构造必要数学声明，禁止一对一冗余 JSON 层。R4 不把覆盖引用当数学等价证明。R5 按依赖和模型预算管理重试。
