# R3 建模边界审查与实测记录

日期：2026-11-08。分支：`codex/modeling-core-refactor`。唯一执行计划仍是 `docs/compute_first_guidance_plan.md`；本文只记录实现与验证证据。

## 实现与判断

R3.1–R3.2 已完成建模内核阶段验收：最终原件Q1与六期同族题均从DOCX重新生成并求解，逐期独立核对通过。这不代表完整产品流程或D2完成。生成链现在是：原件 → InputCatalog/EvidenceProfile → 子题事实快照 → 架构 → 索引/参数绑定 → 程序物化 → **变量、目标、约束共同生成** → canonical ModelIR → 既有编译/执行。完整 ModelIR 的字段与求解器协议保持原格式。

两个实际反例决定迁移边界，不能仅靠调整提示或拆文件处理：

1. 旧实现先确定目标，再生成关系。Q1 得到6760元；后续约束中的指导者未被计入目标，求解器安排没有新手的免费指导活动，并在第8周服务16台而非需求7台以避免保养费用。
2. 第一版仅把目标移到关系阶段。Q1 得到7600元；数据阶段未声明指导者变量，关系阶段又不得增加变量，因此把训练容量写成“新手≤10×全部熟练工库存”。指导者既不占用资源，也不计训练费。

最终将变量声明一并交给数学阶段。前一阶段只拥有索引和经过证据核验的参数，不再冻结尚未构造关系的变量目录。删除旧约束草稿和变量上下文类型，直接迁移内部调用，无兼容入口。`IndexedLinearDataSpec` 负责已物化数据；`IndexedLinearFormulationDraft` 负责全部数学声明，并直接提升为已有 `IndexedLinearModelSpec`。

完整语义校验也移入本次数学声明请求的重试边界，复用既有 `_validate_model_ir_slice`。已验证的参数不重生成；失败的数学声明不能登记覆盖或被提交。最终 canonical 校验仍保留。

## 独立数学参考

参考脚本 `backend/.local/r3_independent_reference.py` 不导入项目代码、编译器或MILP。它直接读取DOCX成本与需求，使用有限状态动态规划优化模块，按最迟需要时间购买载具。逐期解审核脚本 `backend/.local/audit_r3_solution.py` 独立重算需求、构成、购买时滞、训练容量、指导者占用、工作后保养、状态平衡和六项费用。

DP状态为累计可用熟练模块数；上一期工作量由固定需求确定。每次购买p个模块，指导者取ceil(p/容量)，因为训练费高于保养费，增加不必要指导者只会增加成本。先构造可行采购方案作为成本上界，再用每个新增模块至少发生的购买费与训练费界定总采购量，穷举所有可能优于上界的状态。载具可连续使用且无折扣，提前额外购买不会更便宜，因此最迟一期提前购入。

原题7625是**条件参考值**：固定实际需求、初始库存可用、新购下一期可用、工作后保养一期、指导者不能同时工作、训练费对新手与指导者都计收且不重复计保养、无残值。原题训练费与指导活动的解释仍须明确；不能把此数值说成所有解释下唯一答案。合成题正文已明确上述口径。

7600元那轮的购买量恰好相同，但少计5名指导者的训练费50，多计对应保养费25，净差25；缺失的资源占用还会使其他输入上的可行域错误。审核结果保存在该轮`independent_audit.json`，原始模型与解未改动。

## 验证范围与未完成部分

在线runner调用真实摄取、拆题、单子题建模、编译和MILP，**没有运行LLM Reviewer、完整工作流和写作导出**。复用拆题与显式选子题的实验均已分别标明；原件重跑不能用这些实验替代。

最危险的剩余边界是题面→拆题事实→数学充分性：引用某事实并不意味着公式完整表达它，求解器只核验已编译的矩阵。合成题早期出现了虚构歧义与将求解步骤当作子题的问题；最终拆题仍输出“建模”和“求解”两个步骤，本轮自动选择的首个建模子题已生成完整可执行模型，但没有验收第二个子题及完整依赖流程。原题最终公式还直接写入了与原件相符的成本标量，而未处处引用已绑定参数；本次独立核对只证明这些数值正确，不证明参数变更会传播。R4须以独立数学审核和已知遗漏变异为依据，R5处理预算/重试成本；本报告不将其视为完成。

现状摘要：核心流为证据数据→联合数学声明→ModelIR→审核/执行；最危险的剩余边界是来源引用与数学充分性没有等价保证；本次消除了前一阶段冻结变量和目标的耦合，并将完整语义错误纳入阶段重试；完成R3.1–R3.2，下一未完成项为R4.1。R4、R5及D2均未验收。
